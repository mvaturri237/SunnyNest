School Icons on Map — 3 Design Options

13 public elementary schools (Sunnyvale SD, Cupertino USD, Santa Clara USD) shown as icons over the existing rental map. Each option coexists with 5 sample price pill markers and the Sunnyvale boundary so we can judge visual weight. One school per map starts in the hover state so the tooltip is visible.

Map: Leaflet 1.9.4 · OpenStreetMap tiles · Default zoom 12 · Font: Inter · Tokens from docs/design/design-bible.md

Option A — Minimal POI pin

★ Recommended Extends existing POI pattern

A small 24×24px amber circle with a 🏫 emoji — exactly the POI marker spec already in the Design Bible (school color #f59e0b, white border, drop shadow, hover tooltip). The school stays visually quieter than the white price pills, which preserves price-as-primary-signal. Zero new design vocabulary to introduce.

Pros

  • Reuses the existing POI marker pattern — no new design tokens needed.
  • Visually subordinate to price pills (smaller footprint, no text).
  • Stays legible from zoom 10 → 18 with no adjustments.
  • Trivial Leaflet implementation: L.divIcon + one CSS class.
  • WCAG AA — pairs amber color with 🏫 shape; tooltip has 4.5:1+ contrast.

Cons

  • District is not visible without hovering (single color).
  • Identifying a specific school requires hovering each pin.

Tradeoffs

  • Lowest visual weight ↔ lowest information density. Best fit for a map where listings (not schools) are the primary task.

Option B — District-tinted badge (color + shape)

Adds district at a glance

Same hover-tooltip behavior, but the marker encodes the school's district via both color (cyan/violet/pink) AND shape (circle/square/diamond) — color-blind safe per WCAG. A corner legend explains the encoding. Optional: very subtle district polygon tinting could pair with this to reinforce zone boundaries (call out below).

hover state shown
Color-blind safe: shape encodes district independently of hue + optional 8% district polygon tint (not shown)

Pros

  • District is visible at a glance — useful for shoppers comparing zones.
  • Color + shape = passes WCAG "color independence" rule cleanly.
  • Legend gives a teaching moment about the 3-district reality of Sunnyvale.

Cons

  • Introduces 3 new color tokens that aren't in the Design Bible today.
  • More visual weight — three saturated hues compete with price pills.
  • Legend takes corner real estate (collides with Leaflet zoom buttons unless repositioned).
  • Diamond marker requires rotation hack — tooltip needs counter-rotation (extra CSS).

Tradeoffs

  • Best when district choice is a known user goal. Overkill if users mostly filter by price/beds and treat schools as background context.

Option C — Zoom-adaptive label chip

Progressive disclosure

Small pin at zoom ≤ 13 (city-wide view); when the user zooms to 14+ (neighborhood view), each pin expands into a chip with the school's name inline. Hover on either state reveals the full name + address. Shown side-by-side below: left = default zoom 12, right = zoomed-in 14.

Pros

  • No hover required for primary info once user is at neighborhood zoom.
  • Stays quiet at city zoom — won't clutter the default view.
  • Matches a known UX pattern (Google Maps POIs, Mapbox labels).

Cons

  • Chips can overlap each other and price pills when schools cluster (e.g., Bishop + Cherry Chase are ~600m apart).
  • Most complex to implement — needs zoom listener + icon swap + label collision handling (or accept overlap).
  • Adds horizontal text — competes with price pills' typographic weight.
  • Doesn't help users who never zoom in (many keep default zoom).

Tradeoffs

  • Highest information density at zoom ≥ 14 ↔ highest implementation cost. Best if school identity is critical (e.g., a "School Finder" mode).

Recommendation: Option A

The user's stated need is "display schools as icons, show name on hover" — Option A delivers exactly that with the cheapest implementation, the smallest visual footprint, and zero new tokens. It also already exists in the Design Bible as the POI marker spec (school = amber circle + 🏫), so we'd just be activating an unused pattern. If district information later becomes important, Option B can be layered on as a v2 (swap the icon class) without breaking anything.

Open questions to confirm before implementation: (1) Should the school layer be ON by default, or off behind a layer toggle? (2) Should icons stay visible at all zoom levels, or hide at very wide zoom (≤ 10)? (3) Should the popup ever include district / address, or is the name-only tooltip the final spec?
